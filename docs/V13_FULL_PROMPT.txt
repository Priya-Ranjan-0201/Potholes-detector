3.0 Accuracy target (defined up front, measured only on the held-out test sets, never tuned on them):
    - PRIMARY: image-level accuracy and F1 for "contains a road defect: yes/no" >= 90% on the multi-source
      test set, with hard negatives included.

      multi-source test set. If not reached, report the real values with confidence intervals and the
      slices that limit them.

      overall without a documented explanation.

3.1 Fix integrity problems found in Phase 1 first (orientation, colour order, letterbox, coordinate mapping,
    post-processing, parity). Add regression tests with rotated, alpha, grayscale, large and tiny images.
3.2 Replace ad-hoc heuristics with measured, learned behaviour:
    - Train and fine-tune on a larger, multi-source, licensed training set (RDD2022 all countries plus other
      licensed sets), with hard-negative images included as background. Use group-aware splits.
    - Candidate models: YOLO11 (n/s/m) fine-tuned, RT-DETR or D-FINE fine-tuned (only if licence and
      provenance are verified), YOLOv8/YOLO11-Seg for masks. Compare on VALIDATION; the edge model is chosen
      by accuracy per latency.
    - Ensemble: if used, fuse with Weighted Boxes Fusion or similar, with weights and thresholds FIT ON
      VALIDATION (grid or optimisation), each model's scores calibrated first (temperature or isotonic). The
      fixed 0.70/0.30 mix and the consensus boosts are removed unless validation shows they help.
    - Hand-set filters (obstacle blocker, luminance, saturation, geometry, cluster limits, quality gate) stay
      ONLY if an ablation on validation shows they improve precision without hurting recall, and a test on the
      user_cases split does not show regressions. Otherwise delete them. Prefer fixing errors with data
      (hard negatives, more diverse positives) over rules.
    - Hard-negative mining rounds: run on negative images, add confident false positives to training as
      background, retrain, repeat until validation precision stops improving. Active-learning round on the
      user's failure images (after splitting them into train-eligible and held-out parts; held-out part is
      never trained on).
    - Augmentation for domain shift: brightness/contrast, blur, noise, JPEG compression, rain/fog/low-light,
      scale, rotation within a few degrees, mosaic on/off ablation.
    - Resolution study (640/800/960/1280) for small and far potholes; tiling for very large images.
    - Calibration: report ECE and reliability diagrams; choose the operating threshold on validation for a
      stated precision/recall trade-off.
    - Ablation table (generated): each change vs the baseline with seed spread (>= 3 seeds when budget allows).
      Keep a change only if it improves validation beyond seed spread and does not hurt held-out slices.
3.3 Video:
    - Pipeline: decode with correct rotation, sample frames adaptively, detect, track (ByteTrack/BoT-SORT),
      require a minimum track length and mean confidence, merge a track into one defect event, keep the best
      frame, smooth over time. Never report per-frame duplicates as separate defects.
    - Metrics on the video test set: event precision, recall, F1 (a defect event is matched if its track overlaps
      a ground-truth event in space and time), false alarms per minute and per km when speed is known, ID
      switches, duplicate rate, latency per frame, end-to-end FPS. Target: event-level precision and recall
      >= 90% on the video test set, reported with confidence intervals; if not reached, report honestly.
3.4 Image-quality and input handling: reject or warn on unusable inputs (too dark, blurred, not a road scene)
    with a clear message instead of a wrong answer. Learn the "not a road / unusable" decision from data or use
    a documented, validated rule, and report its false-reject rate.
3.5 Severity and measurement: pixel and relative-area measurements only; no centimetre or depth claims.

3.6 Repair verification (ORB + RANSAC): evaluate on real before/after pairs; if none exist, label the feature

## What to know before you rely on this

**The 90% target.** I can't promise it. The prompt makes the agent attempt it honestly: it is measured on a large, multi-country held-out set that includes hard negatives, and nothing is tuned on the test data. If the real number is lower, the report says so with the sample size and a confidence interval.

**Why new images give wrong results.** From your README, the likely causes are:
- **Small test set:** the 85.75% mAP comes from only 50 images and 105 labels.
- **Hand-set rules:** filters for brightness, saturation and box shape were probably tuned on a few images.
- **Fixed ensemble weights:** the 70/30 mix combines models whose scores are not on the same scale, and it was not fitted on validation data.
- **Possible mismatch:** external models that may never have been trained on road damage, plus preprocessing details such as phone-photo rotation and colour order.

Phase 1 tests each of these. Phase 3 removes any rule that cannot prove it helps.

**No fake data.** This means an empty app on first run. It fills only from real uploads and from running the real pipeline over licensed evaluation images. The earlier demo seed data is removed.

**Cleanup safety.** Files move to a staging folder first. The agent restores any item that breaks the tests, and history stays intact.

**One note on "looks human-written".** The prompt makes the code and README clean and natural, and also adds a short `ABOUT_THE_BUILD.md` listing which AI tools helped. If your college requires AI-use disclosure, you'll want that.
